`.durations.json` is seconds per test file; `sequencer.ts` balances `vitest --shard` by it and `check:quick`'s test budgets (`scripts/gate-select.mjs`) read it.
A file's seconds are its whole cost in its worker, import and collect included (`durations-reporter.ts`); a vitest JSON report counts test time only and is refused.
A stale or missing entry costs shard balance, never correctness (an absent file counts as the median, placed after every recorded file, so it moves no recorded file); it is not a drift artifact.
Refresh as the median of three green PR runs (each Node 22 shard uploads `test-durations-<n>`), one directory per run: `gh run download <run id> -p 'test-durations-*' -D <dir>`, then `node scripts/gen-test-durations.mjs -o test/.durations.json --median <dir1> <dir2> <dir3>`.
Nightly's artifact is one map for the whole suite: `gh run download <run id> -n test-durations -D <dir>` gives `<dir>/test-durations.json`, which counts as one run.
`--drop <file>` forgets a row whose file changed its cost in the same change (the next refresh records it). Locally: `TEST_DURATIONS_OUT=d.json npx vitest run --reporter=default --reporter=./test/durations-reporter.ts`.
