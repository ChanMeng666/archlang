`.durations.json` is seconds per test file; `sequencer.ts` balances `vitest --shard` by it.
A file's seconds are its whole cost in its worker, import and collect included (`durations-reporter.ts`); a vitest JSON report counts test time only and is refused.
A stale or missing entry costs shard balance, never correctness (an absent file counts as the median, placed after every recorded file, so it moves no recorded file); it is not a drift artifact.
Refresh from a green PR run (each Node 22 shard uploads `test-durations-<n>`): `gh run download <run id> -p 'test-durations-*' -D <dir> && node scripts/gen-test-durations.mjs <dir>/*/test-durations-*.json`; or from nightly's `test-durations` artifact the same way.
Locally: `TEST_DURATIONS_OUT=d.json npx vitest run --reporter=default --reporter=./test/durations-reporter.ts && node scripts/gen-test-durations.mjs d.json`.
