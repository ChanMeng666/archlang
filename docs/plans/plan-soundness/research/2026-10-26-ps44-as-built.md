# PS4.4 as built (2026-10-26)

Record for card PS4.4: brief-bound dimensions (provenance). Branch `feat/brief-bound-dimensions-ps44`.
Rule: `src/analyze/gross-area.ts`. Intent: `src/intent.ts`. Tests: `test/brief-bound.test.ts`.

## What shipped

- **A gross internal area fact.** `describe().totals.gross_internal_area_m2` is the floor inside
  the inner faces of the storey's `exterior` walls, beside the centreline `floor_area_m2`, on every
  storey (`levels[i].totals` too). A storey with none gets `gross_internal_area_omitted` with a
  typed reason instead. Every summary gains exactly one of the two keys.
- **Three intent assertions, all gating.**
  - `grossInternalAreaM2`: a band, with the same rules as `totalAreaM2`.
  - `roomDimensions[].widthMm` / `depthMm`: a band on one room's centreline extent along x / y.
  - `roomDimensions[].sizeMm`: an exact `w × h`, in either orientation, within `tolerance` mm
    (default 0).

  A room is bound by `room`: its id, else its exact label.
- **New catalogued codes.** A miss is `E_INTENT_GROSS_AREA` or `E_INTENT_ROOM_DIMENSION`. A measure
  with no value is `E_INTENT_UNMEASURED`, a refusal like `E_INTENT_NO_SITE`.
- **Measures reported.** `validate --intent` and `score --brief` print one `measure` line per
  brief-bound assertion. In `--json` the rows sit under `intent.measures`, each with `path`, `what`,
  `unit`, `measured`, the signed `residual` and `pass`, or a `reason`. `IntentCheckResult.measures`
  and `AssertionResult.measure` exist only when the intent asserts one, so every other result and
  payload is byte-identical.
- **Records and docs.** Schema (`gen:intent-schema`), error codes (`gen:errors`), one line in
  `docs/intent.md`'s field table plus a "Brief-bound sizes" section, one sentence in
  `skills/archlang/SKILL.md` step 8 (regenerated into `llms-full.txt`, the plugin copy, the context
  size and `docs/cli-reference.md`), a `docs/analysis.md` row, and the `docs-site/agents.md` sample.
  `spec.llm.md` is untouched: the intent file's grammar is not in it, and the 236 units of headroom
  are left for PS4.3a.

## Decisions

1. **What counts as the exterior ring.** The ring is every wall of category `exterior`, joined by
   the one wall joinery (`joinWallSet`) with openings uncut, which is the drawing's own outline.
   This is the convention `roof overhang` already reads ("the plan's closed `exterior` wall"). It
   also covers a shell written as separate runs that meet (walls-first) and a derived ring that an
   authored wall splits. The joined outline's loops nest. Each outermost loop with exactly one hole
   is a building. Its GIA is the hole's closed-form area (`loopArea`: shoelace plus the exact
   circular segment of each arc) less every loop standing in the hole: a courtyard ring's outer
   face, or a free-standing exterior run. Several buildings on one storey sum. "Per storey and
   summed" was read as per storey, summed over the storey's buildings. A building-wide sum over
   storeys would be a second new key, so it was left out. The top-level `totals` are the lowest
   storey's, as for every other total.
2. **The figure is never guessed (ADR 0005).** It is refused with a reason in four cases:
   - `no-closed-exterior-ring`: no exterior wall encloses anything (an open run, a room-only
     sketch, an open site);
   - `exterior-ring-subdivided`: an exterior wall divides the enclosure, so which side is the
     building is not stated;
   - `nested-exterior-rings`: something is enclosed inside a courtyard ring;
   - `too-much-work` (a counted cap) or `inconsistent`.
3. **Budget.** `describe()` has no step meter. The work is capped by counts charged before it runs,
   as `src/analyze/wall-faces.ts` does: the wall-face segment cap (`MAX_FACE_WALL_SEGMENTS`) and
   contact cap (`MAX_WALL_CONTACTS`) before the joinery, then `MAX_GROSS_AREA_TESTS` = 4,000,000
   for loops × outline edges before the containment pass. The figure is not computed inside
   `compile()`.
4. **GIA reads no room.** It is the shell's enclosure, partitions included. On a plan whose rooms do
   not cover the shell, it can exceed the centreline sum. In the corpus that happens on `library`
   (1575.49 against 1545.06: floor no room covers) and `courtyard-house` (175.84 against 163: the
   court is bounded by partition-category walls, so it reads as enclosed floor). Both are correct
   readings of the rule. See open question 1.
5. **Room dimensions are on centrelines.** They are read off the room's own rectangle: the
   `floor_polygon` is accepted only when it has four vertices and axis-parallel edges, never from a
   bbox. A polygon or circular room is refused (`room-not-rectangular`). The brief binds GIA to the
   client's figure. A stated room size binds the `size` the author writes, and every message says
   "on centrelines". `width` is the extent along x and `depth` along y. `sizeMm` ignores orientation,
   because "a 3.2 × 3.6 m bedroom" names a rectangle, not which way it faces. The orientation that
   fits better is reported (a tie keeps the written one). Use `widthMm`/`depthMm` to bind an
   orientation.
6. **The selector.** The id is tried first, then an exact label. If no room matches, the reason is
   `room-not-found`; if two rooms share the label, it is `room-ambiguous` (bind by id). Rooms are
   read on the lowest storey, like every other room assertion. Messages name the room by its quoted
   label, or by the shared `src/naming.ts` phrase when it has none ("the kitchen width 3000 mm …").
   Never by id.
7. **Residuals.** A band residual is 0 inside the band, `measured − min` below it and `measured −
   max` above it. A size residual is `measured − target` per axis. m² residuals are rounded to 0.01,
   the figure's own precision.
8. **Subscores.** The three kinds join the `area` subscore. No corpus intent uses them, so
   `JUDGE_VERSION` stays `2` (its rule: new kinds unused by the corpus do not bump it).
9. **Not touched:** the parser, `src/ir.ts`'s resolve order, `describe().keeps` (PS4.3a), and
   `packages/mcp`. The MCP `validate` tool's intent block does not carry `measures`. Its baked
   intent-schema resource refreshes only with a version bump (open question 3).

## Open questions

1. **Courtyard bounded by partitions.** `courtyard-house`'s court reads as enclosed floor because
   its walls are partitions. Should an `outdoor` surface or a `void` inside the shell be
   subtracted? It was left out: no corpus plan declares one there, and the rule would need its own
   decision.
2. **A subdivided shell.** Should it report the enclosure inside the outer boundary, partitions
   and exterior walls included? That is the RICS reading, and it would give the walls-first
   apartment 11400 × 7200 = 82.08. It is refused today, because which walls are "perimeter" is not
   stated.
3. **MCP.** `packages/mcp`'s `validate` tool and its baked intent schema need a version-bumped
   release to carry `measures` and the new fields.
4. **Building-wide figure.** A summed GIA across storeys, for a brief that states a whole-house area
   on a multi-storey plan, needs a key outside `totals` (or a `levels` sum by the reader).
