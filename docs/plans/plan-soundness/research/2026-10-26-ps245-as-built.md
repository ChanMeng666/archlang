# PS2.45 as built (2026-10-26)

Record for card PS2.45 (`finish` furnishes small wet rooms the WC rule accepts). Paths are
relative to the repository root. Never rewrite this file; correct a conclusion in the card it
affects (README §8).

## What shipped

`src/furnish.ts`. A bathroom or WC (every use of the room is `bath` or `wc`) that the
piece-by-piece run would leave empty is now tried as whole sets before the stage reports it:

- **Layouts, in a fixed order.** One layout per position the stage's own candidates give the pan
  (`Site.candidates`: walls with no door first, then no window, then longest; corners, 450 mm off
  the side face, before the middle). The layout is the first completion of that pan, depth first
  in the same order, with the basin and then (in a bathroom) the `bathtub` or `shower`. Every
  piece must clear the room's geometry (`Site.fits`: the clear floor, each door's approach and
  swing, the pieces before it and their front strips), and every pan's two sides must keep
  `WC_SIDE_MM` to the walls and to the other pieces, measured with `W_WC_SIDE_CLEARANCE`'s own
  strips and obstacles (`measureWcSides`, `wcWorld`, `isShort` from
  `src/lint/clearance-measure.ts`, imported, not retyped).
- **Abutting positions** (`Site.abutting`). Besides the corners and wall middles, a piece is
  offered with one end against the end of a placed piece, of its front strip, or of a door's
  approach on the room's floor, on every wall a statement can name. This is what puts a basin in
  the gap between the door's approach and the floor kept in front of the pan in a 1.0 m WC room.
  Only the set search asks for these positions.
- **The gate.** Each layout costs one compile check through the stage's never-worse `refusal`
  (default ruleset plus the universal profiles, conflicts, errors); the first accepted is written.
  At most `MAX_SET_CHECKS_PER_ROOM` = 4 layouts are checked. A room no layout fits keeps the note
  the piece-by-piece run gives it (the same text, codes and span).

`scripts/probe-finish-wet-rooms.ts` reproduces the sweep; `docs/furniture.md` says what the
stage does; ADR 0025 §6 carries a dated amendment and the bound `1 + 17 × rooms` (§6, §11).

## Decisions

1. **Only rooms left empty reach the set search.** The piece-by-piece run is unchanged, its own
   budget stays 13 (`MAX_PIECE_CHECKS_PER_ROOM`), and the set search is called only at the three
   places that run ends with the room empty. So every room the stage furnished before keeps its
   statements byte for byte: over the sweep, 0 rooms lost and 0 changed against `main`; over the
   examples, every `FINISH_DIGESTS` row is unchanged. Why not a set search first: it would move
   every wet room the stage already furnishes, for no soundness gain (they already pass the law).
2. **450 mm, never 400.** The brief allows 400 (the default rule's figure) when 450 cannot be
   met. The never-worse law holds under `accessibility-advisory` too (ADR 0025 §7 as amended
   2026-10-25), whose `wcSideClearanceMm` is 450, so a pan at 400 gains `W_WC_SIDE_CLEARANCE`
   there and the gate refuses it; offering one would only spend a check. The figure is
   `WC_SIDE_MM`, the maximum of the rulesets' own `wcSideClearanceMm`, as before PS2.45. If the
   law is ever narrowed to the default ruleset, the figure falls to 400 with it, unedited.
3. **Every piece of the row is required in a set.** The bath row's `bathtub`/`shower` is optional
   in `FURNISH_TABLE` but is the piece that defines a bathroom (`definingItems`), and a bath
   without it is left empty anyway, so the set search never writes a set without it.
4. **One layout per pan position.** A refused layout moves to the next pan position, not to the
   next completion of the same pan: the refusals seen were the pan's, and a completion-level
   retry would spend the 4 checks on one pan. Measured: with the bound at 1, the sweep furnishes
   209 baths; at 4 and at 12, 213. The WC count is 275 at each.
5. **The stage's front-strip rule stays stricter than the lint.** `W_FURN_CLEARANCE` ignores a
   services fixture standing in another's clear floor (a basin in front of the pan), and the
   stage does not. Relaxing it would furnish more of the 1.0 m rooms, with a basin standing in the
   floor in front of the pan; the card asks for sets the rules accept, not every set they accept,
   so the stricter reading is kept. These rooms stay empty and are listed below.
6. **Steps.** `finish` is a source-to-source transform outside `compile()` (ADR 0006/0024), with
   no step meter running; its budget is the count of compile checks, charged before each layout
   is rendered and checked. The geometric search is bounded and runs no compile: on each of at
   most four walls a piece has three slots plus `2 × (a + 2p)` abutting positions per word and
   footprint (`a` door approaches on the room's floor, `p` pieces before it, at most two).
7. **Sweep reconstruction.** The red team's 918-room probe set was never checked in (no script in
   the PR, the record or the scratch directories). `scripts/probe-finish-wet-rooms.ts` rebuilds it
   from the record's parameters: one room in a 200 mm exterior wall, `w` 1200–3600 by 150 and `h`
   1200–3600 by 300 on the centrelines (17 × 9), one 800 mm door in the middle of the top wall
   swinging in or out, three classes (`uses bath`, `uses wc`, a room labelled "Ensuite" with no
   `uses`): 918 rooms. It does not reproduce the record's counts (pre-#252 `main` 276 WC / 144
   bath / 0 ensuite there, 286 / 176 / 176 here): the door position and the ensuite tagging differ
   (here "Ensuite" reads as a bath through the vocabulary, so that class equals the bath class).
   The trend is the same, and the comparison below runs every tree on the same rooms.
