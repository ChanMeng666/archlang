# PS2.22 and PS2.29 as built (2026-10-26)

Record for cards PS2.22 (`W_ALIAS_MATCH` quotes a room id) and PS2.29 (id-free lint messages), one
PR: PS2.22 folded into PS2.29. The iron law (`docs/agents/iron-laws.md`; owner, 2026-10-18): a
`message` never quotes an element id. Ids live in the `hint`. Branch `fix/id-free-messages-ps229`.
Red-team round 1 changed the shape of the first version (place words, a missing space, hints that
lost ids, a quadratic cost); this note describes the head after it.

## The test, red before and green after

`test/lint-messages-id-free.test.ts` builds the forbidden set from each plan's own ids
(`resolvePlan` over every storey: every element id, every wall id, so `A|B`, `A|B:open`,
`exterior` and `exterior#n` are in it on a `walls from rooms` plan). An id with a character that is
not a letter counts wherever it stands as a whole token; a plain-word id (`hall`, `exterior`) counts
only when quoted and when the quoted string is not a label or category the plan itself uses. It reads
three channels per plan: `lint()`, `taste()` (every `message` in the report) and the `W_ROOM_OVERLAP`
warning of `compile().diagnostics`. The plans: `examples/` (`SHIPPED_EXAMPLES`), `eval/goldens`,
`docs/plans/plan-soundness/audits/first-contact-plans/**`, `test/defect-corpus`, `test/taste-corpus`,
`test/fixtures`, every `W_*` catalogue example (wrapped in the smallest plan, under the profile its
comment names), two inline plans for rules nothing else fires (`W_DIM_INSIDE`,
`W_FIXTURE_WRONG_ROOM`) and a third for `W_ALIAS_MATCH` on an unlabelled `r_carport`. Each is also run
as a twin with every `label "…"` clause taken away, which is how an unlabelled room, the one that
leaked, is exercised everywhere, and with every id then renamed to `zz_<id>` (round 1), so a plain-word
id (`bath`, `kitchen`) or one equal to a furniture category is as visible as `r_bath`; an id that is a
word of the language (`left`) is kept and covered by the quoted-id rule. A last assertion fails when
any of the sixteen rules that once quoted an id was never read by the sweep, so the test cannot go
green by not firing them.

Run against `origin/main` (the test file copied into a clean worktree of `main`, `src/` as on main):
RED_NUMBERS After the change: 0 and 0.

## What shipped

One phrase builder, `src/naming.ts` (a neutral module: `lint()`, `taste()` and the resolver all import
it, and `src/ir.ts` no longer reaches into `src/lint/`), used by `lint()` (`ctx.nameOf`, `ctx.nameAs`,
`ctx.placeOf`, `ctx.placeAt`), `taste()` (`namesOf`) and the compile-channel `W_ROOM_OVERLAP`
(`roomOverlapNamer`). A labelled room is named by its quoted label, byte-identical to before. An
unlabelled room is named by what the plan knows of it, in this order:

1. its use word, when it has one and no other room has it: "the kitchen". A LABELLED room of the same
   use counts as another room of that use, so "the kitchen" is never ambiguous beside `Kitchen "Kitchen"`.
   A room with several uses is named by the use the message is about ("the bedroom" to
   `W_BEDROOM_NO_WINDOW`), when it has it;
2. where it stands on the storey, when that word is not enough or the room has no use: "the bedroom
   on the left of the plan", "the room in the top left of the plan". The position is the room's
   label point (`polygonLabelPoint`, a point inside the floor), read against the OUTLINE of the
   storey (the extent of every room's floor), in page terms. An axis the storey is not at least one
   and a half rooms long along says nothing, so two equal rooms side by side are "on the left" and
   "on the right" (not "top left" and "bottom right" for 10 mm of offset), and a room a third of the
   way down a plan is in the middle row, not at the top;
3. when use and place still tie with another room, its size first, "the 3.2 × 2.4 m bedroom in the
   top left of the plan" (a polygon or circle by area, "the 20 m² room …");
4. when even that ties, its place in reading order, in one bracket: "… (2 of 2)". A rule's own bracket
   after the name is folded into it ("… (1 of 2; 20 m²)"), never two brackets in a row;
5. the storey, "on level 2", only on a plan of several storeys (a plan of one `level` block says
   nothing: the storey count rides on `BuildingContext.storeyCount`, `ResolveExtras.storeyCount` and
   `taste()`'s `storeys.length`).

Never an invented label, never the id. `W_ALIAS_MATCH` is about how the use was *read*, so its
unlabelled message names the room by place alone (`placeOf`: "the room on the left of the plan"), and
leaves the word taken from the id to a second hint. Naming a room costs its own group, not the
storey (indexed by use and place), and an outdoor surface is named only when it warns.

Other things a message used to name by id, now named as a reader would (the id is in the hint where an
agent needs it, and was added there where it was nowhere):

| thing | now |
|---|---|
| a wall (`W_POCKET_RUN`) | `wallNamed`: "the partition between the kitchen and the hall" (derived, or a room on each face), "the exterior wall of the kitchen", else its kind and place ("the exterior wall at the top of the plan"), the line it runs on only for a curved wall or a plan with no room |
| a wall (`W_DOOR_NEAR_CORNER`, `W_OPENING_NOT_DIMENSIONED`) | its kind and the line it runs on, `wallPhrase`: "the exterior wall at y 8000" (moved with `axisLine` and `openingName` into `src/lint/element-phrases.ts`) |
| another door (`W_SWING_OBSTRUCTED`) | "the swing of the exterior door into \"Hall\""; the id is a new last hint (two doors between the same rooms are otherwise ambiguous) |
| the entrance (`W_CIRCUITOUS_PATH`) | "the entrance (the exterior door into \"Hall\")"; the id in a new hint |
| a window or door (`W_OPENING_NOT_DIMENSIONED`) | `openingName` plus its wall |
| a dimension (`W_DIM_INSIDE`, `W_DIM_OVERLAP`) | "the dimension from (0, 4000) to (5000, 4000)" |
| an outdoor surface (`W_OUTDOOR_OVERLAPS_ROOM`, `W_BALCONY_NO_DOOR`) | its label, else "the balcony off the living room" (the room it touches or lies nearest, within a wall thickness), else "the lawn in the bottom left of the plan"; ties "(1 of 2)"; the surface's id is a new hint |
| a stair (`W_STAIR_UNMATCHED`) | "the stair in the middle of the plan", plus "on level 1" on a plan of several |
| the declared room (`W_FIXTURE_WRONG_ROOM`) | `is not inside "Bed", the room it is declared in`; the id is in the hint |
| two rooms (`W_ROOM_OVERLAP`, compile) | `Rooms "A" and "B" overlap`; unlabelled: "The kitchen and the bedroom on the left of the plan overlap"; two rooms with one label are told apart by place, then "(the first)" and "(the second)"; on a plan of several storeys, the level |

The message sites that took a room through `ctx.labelOf` now take `ctx.nameOf`; `labelOf` stays for
hints. A HINT keeps naming a room by its label or its id, as it did: round 1 restored the hints that
the first version had put through the message wording (`W_OPENING_AT_JUNCTION`, `W_OPENING_OVERLAP`,
`W_FOOTPRINT_TRANSPOSED`, `W_LEAF_ACROSS_DOORWAY`, `W_WET_ROOM_DOOR`, `W_ROOM_VIA_PRIVATE`,
`W_ENTRANCE_INTO_PRIVATE`, `W_CONNECTOR_AMBIGUOUS`), and the messages no longer say the same noun
twice ("opens straight into the kitchen, a kitchen"). `annotations.ts` uses the shared builder. Every
coordinate in a new message is `(x, y)` with the space; `W_DIM_TEXT_MISMATCH` joined it.

Decisions beyond the card:

- *Page words, not compass words.* "top left" and "bottom" read against the sheet; "north" needs the
  plan's `north` and `site`, and a lint message must not depend on them (ADR 0032 decision 6 keeps
  `taste()` a function of the plan alone).
- *Authored ids too.* A door the author gave an id is also named by its rooms in a message.
- *The compile channel is `W_ROOM_OVERLAP` only, here.* The first version said the other resolver
  diagnostics merely quote what the author wrote. Red-team round 1 showed that is not so: an
  unauthored generated id such as `door_2` in `W_DOOR_OFF_WALL` reaches `validate --json`'s
  `next.message`, and `E_OPENING_NIB` prints a derived wall name. They are filed as PS2.57 with the
  `describe()` captions and the CLI coverage lines that print room ids.
- *`W_ROOM_OVERLAP` on labelled rooms now says the label, not the id* (`Rooms "Living" and "Bath"
  overlap` where it said `Rooms "r_living" and "r_bath"`).

## Corpus movement

**`lint()` over `examples/`, `eval/goldens` and the fixtures: no row moves in rule or count.** The
`byte-identity-baseline.ts` table, `taste-digests`, `finish-digest` and every example digest are
unchanged, and `eval/judge-fixture.json` is untouched. The rules whose message text moved for a plan in
which every room has a label (the "changed for labelled plans" table, which a re-run against `main`
checks): `W_POCKET_RUN`, `W_DOOR_NEAR_CORNER`, `W_SWING_OBSTRUCTED` (the other door),
`W_CIRCUITOUS_PATH`, `W_OPENING_NOT_DIMENSIONED`, `W_OUTDOOR_OVERLAPS_ROOM`, `W_BALCONY_NO_DOOR`,
`W_ROOM_OVERLAP`, `W_DIM_INSIDE`, `W_DIM_OVERLAP`, `W_DIM_TEXT_MISMATCH` (the space in `(x, y)`),
`W_STAIR_UNMATCHED`, `W_FIXTURE_WRONG_ROOM`. Any other rule's message is byte-identical to `main`'s for
a labelled room.

**The re-run comparison (round 1).** The corpus and every catalogue example, linted under `main`'s
`src/` and under this head, as written, label-stripped and, where a plan has an unlabelled room,
with every room labelled; default and `accessibility-advisory`: RERUN_NUMBERS

**Digest rows.** 23 pinned digests in 8 tables moved (26 digest inputs: three are `not.toBe` probes
that need no re-pin), by dumping the digest input from `main` and from this head (the digest body
patched to append its input to a file, applied to both, then reverted). Every moved row differs in
message text only (blanking every `"message"` value makes the two byte-equal), the changed messages are
all rules that name an unlabelled room (`W_ROOM_DISCONNECTED`, `W_HABITABLE_NO_WINDOW`,
`W_BEDROOM_NO_WINDOW`, `W_ROOM_MISSING_DEFINING`, `W_ROOM_NO_FIXTURE`, `W_ROOM_UNREACHABLE`,
`W_BOUNDARY_NO_WALL`, `W_WET_ROOM_DOOR`) and every old message quotes a bare id (`r0.r`, `r1`,
`bath`); the one row that moves beyond message text is `import-module-lets` `capped-wet-room.laundered`
(its `W_SWING_OBSTRUCTED` gains the new door-id hint). Tables and rows: `furniture-relations-digests`
(1), `import-module-lets` and `while-byte-identity-baseline` (`schedule-sheet`, `capped-wet-room.laundered`),
`openings-between-digests` (1), `segment-select-digests` (5), `swing-building-digests` (4),
`wall-between-around-digests` (1), `walls-from-rooms-digests` (8). Each re-pinned line carries its
reason. The first version of this PR re-pinned 41 rows, 20 of them over a lost space in
`has no${…}` (`has nofixtures`); round 1 restored the space, reverted every table to `main`'s and
re-pinned from the corrected output.

Moved over unlabelled rooms in the corpus (not digest-pinned): the first-contact plans' `taste()`
messages (`"living" ranks 2 of 5 rooms …` becomes `The living room on level 0 ranks …` on the
townhouse, which has storeys; `The living room ranks 4 of 10 …` on the house), and the defect corpus's
`bath-open-side` pair and `schedule-sheet`.

Tests that asserted an id in a message were rewritten to assert the new wording and, where the id is
still wanted, to read it from the hint. `lint-fix-texts` now keys unlabelled rooms by the phrase their
message uses, and pins the labelled wording (`has no fixtures`). `grid-index` and
`room-overlap-oracle` keep their pair logic verbatim and take only the wording from `roomOverlapNamer`.
