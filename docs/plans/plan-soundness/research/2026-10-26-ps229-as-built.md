# PS2.22 and PS2.29 as built (2026-10-26)

Record for cards PS2.22 (`W_ALIAS_MATCH` quotes a room id) and PS2.29 (id-free lint messages), one
PR: PS2.22 folded into PS2.29. The iron law (`docs/agents/iron-laws.md`; owner, 2026-10-18): a
`message` never quotes an element id. Ids live in the `hint`. Branch `fix/id-free-messages-ps229`.

## The test, red before and green after

`test/lint-messages-id-free.test.ts` builds the forbidden set from each plan's own ids
(`resolvePlan` over every storey: every element id, every wall id, so `A|B`, `A|B:open`,
`exterior` and `exterior#n` are in it on a `walls from rooms` plan). An id with a character that is
not a letter counts wherever it stands as a whole token; a plain-word id (`hall`, `exterior`) counts
only when quoted and when the quoted string is not a label or category the plan itself uses. It reads
three channels per plan: `lint()`, `taste()` (every `message` in the report) and the `W_ROOM_OVERLAP`
warning of `compile().diagnostics`. The plans: `examples/` (`SHIPPED_EXAMPLES`), `eval/goldens`,
`docs/plans/plan-soundness/audits/first-contact-plans/**`, `test/defect-corpus`, `test/taste-corpus`,
`test/fixtures`, every `W_*` catalogue example (wrapped in the smallest plan, under the profile its
comment names), two inline plans for rules nothing else fires (`W_DIM_INSIDE`,
`W_FIXTURE_WRONG_ROOM`) and a third for `W_ALIAS_MATCH` on an unlabelled `r_carport`. Each is also run
as a twin with every `label "…"` clause taken away, which is how an unlabelled room, the one that
leaked, is exercised everywhere. A last assertion fails when any of the sixteen rules that once quoted
an id was never read by the sweep, so the test cannot go green by not firing them.

Run against `origin/main` (the test file copied into a clean worktree of `main`, `src/` as on main):
**35 rows as written** (10 corpus, 23 catalogue, 2 inline) **and 861 rows in the label-stripped
twins**, in 37 rules plus taste. After the change: 0 and 0. The 10 corpus rows as written are listed
below; the rows over unlabelled twins are the same rules with a room named by its id.

## What shipped

One phrase builder, `src/lint/phrases.ts`, used by `lint()` (`ctx.nameOf`, `ctx.placeOf`), `taste()`
(`namesOf`) and the compile-channel `W_ROOM_OVERLAP` (`roomOverlapNamer`). A labelled room is named by
its quoted label, byte-identical to before. An unlabelled room is named by what the plan knows of it, in
this order:

1. its use word, when it has one (`roomUses`: declared `uses`, or read from the label or id as every
   rule already reads it): "the kitchen", "the bedroom";
2. where it stands, when the use word alone would not tell it from another unlabelled room or when it
   has no use: "the bedroom on the left of the plan", "the room in the top left of the plan". The
   position is the room's label point (`polygonLabelPoint`, a point inside the floor) read against the
   extent of the storey's label points, in page terms (the top of the sheet is the top), so no `north`
   is needed and a bounding box is never used;
3. its place in reading order when use and place still tie: "(2 of 2)";
4. the storey on a multi-storey plan: "on level 2".

Never an invented label, never the id. `W_ALIAS_MATCH` is about how the use was *read*, so its
unlabelled message names the room by place alone (`placeOf`: "the room on the left of the plan"), and
leaves the word taken from the id to a second hint.

Other things a message used to name by id, now named as a reader would (the id is in the hint where an
agent needs it):

| thing | now |
|---|---|
| a wall (`W_POCKET_RUN`, `W_DOOR_NEAR_CORNER`) | its kind and the line it runs on, `wallPhrase`: "the exterior wall at y 8000" (moved with `axisLine` and `openingName` into `src/lint/element-phrases.ts`, shared with `openings.ts`) |
| another door (`W_SWING_OBSTRUCTED`) | "the swing of the exterior door into \"Hall\"" (`openingName`) |
| the entrance (`W_CIRCUITOUS_PATH`) | "the entrance (the exterior door into \"Hall\")"; the id in a new hint |
| a window or door (`W_OPENING_NOT_DIMENSIONED`) | `openingName` plus its wall |
| a dimension (`W_DIM_INSIDE`, `W_DIM_OVERLAP`) | "the dimension from (0,4000) to (5000,4000)" |
| an outdoor surface (`W_OUTDOOR_OVERLAPS_ROOM`, `W_BALCONY_NO_DOOR`) | its label, else "the balcony off the living room" (the room it touches or lies nearest, within a wall thickness), else "the lawn in the bottom left of the plan"; ties "(1 of 2)" |
| a stair (`W_STAIR_UNMATCHED`) | "the stair in the middle of the plan on level 1" |
| the declared room (`W_FIXTURE_WRONG_ROOM`) | the room as above; the id in the hint |
| two rooms (`W_ROOM_OVERLAP`, compile) | `Rooms "A" and "B" overlap`; unlabelled: "The kitchen and the bedroom on the left of the plan overlap"; two rooms with one label are told apart by place, then "(the first)" and "(the second)" |

The remaining message sites that took a room through `ctx.labelOf` (every rule in `per-room.ts`,
`reachability.ts`, `circulation.ts`, `circulation-facts.ts`, `enclosure.ts`, `privacy.ts`,
`room-contents.ts`, `site.ts`, `openings.ts`, `doors.ts`) now take `ctx.nameOf`; `labelOf` stays for
hints. `taste()`'s `namesOf` uses the same builder.

Decisions beyond the card:

- *Page words, not compass words.* "top left" and "bottom" read against the sheet; "north" needs the
  plan's `north` and `site`, and a lint message must not depend on them (ADR 0032 decision 6 keeps
  `taste()` a function of the plan alone).
- *Authored ids too.* A door the author gave an id is also named by its rooms; the old
  `W_LEAF_ACROSS_DOORWAY` hints that quote an authored id are kept (a hint is where an id belongs).
- *The compile channel is `W_ROOM_OVERLAP` only.* Other resolver diagnostics (`W_DOOR_OFF_WALL`,
  `E_*`) quote what the author wrote at the span they point at, and say "unknown id": naming the
  author's own word is the point. They are out of PS2.29; the sweep does not read them.
- *Hints may keep ids.* A hint that already quoted a room by `labelOf` keeps it.
- *`W_ROOM_OVERLAP` on labelled rooms now says the label, not the id* (`Rooms "Living" and "Bath"
  overlap` where it said `Rooms "r_living" and "r_bath"`). This is the one change to a message over
  labelled rooms with no unlabelled room in it.

same span". The one-line probes that assert a digest is *not* a value (`not.toBe`) moved too and need no

  the drafting layer is read off the sheet. Not moved.
