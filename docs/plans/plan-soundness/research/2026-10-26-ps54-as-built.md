## What shipped

- **`arch preview <file> --review [-o out.png] [--width] [--scale] [--level] [--json]`.** One PNG:
  1. the plan exactly as `preview` draws it (the default `compile()` SVG, embedded byte for byte);
  2. the access graph from `describe().access` for the storey: each room a small hollow ring with a
     paper halo at its label point (`roomLabelAnchor`, so from the shape), solid when reached from an
     entrance on this storey and dashed grey when not; one edge per door or opening, drawn from each
     room's node through the connector; ambiguous connectors dashed grey; entrances marked, captioned
     `MAIN ENTRANCE`, or `ENTRANCE (main: a tie)` when `mainEntrance` is a tie;
  3. every element a warning names ringed, with a tag of numbered badges and codes (without `W_`) on
     a paper backing;
  4. a legend: number, code and the message exactly as `lint` prints it (id-free); a mark that rings
     nothing says why (see below);
  5. a strip of close-ups of the flagged doors, windows, openings and furniture pieces, one tile per
     element titled with its numbers and codes, at most 24 (the first in mark order); the strip's
     heading says "+N close-ups not drawn" when there were more.
- **`--json`** adds `review: true`, `rings` (how many marks ring something), `marks[]` (`n`, `code`,
  `message`, `channel`, `span`, `line`, `col`, `file` when imported, `ringed[]` of `{ id, kind, box }`
  in plan mm, and `unringed: { reason, copies? }` when it rings nothing or not everything it names),
  `crops[]` (`n[]`, `element`, `box` in plan mm) and `cropsOmitted[]` (the marks whose close-up was
  not drawn). `diagnostics` is what plain `preview` reports: `compile()`'s warnings for every storey,
  then the render's own. Ids appear in the JSON, which an agent edits by, never in the legend.
- **Teaching.** Manifest flag and example (regenerated into `docs/cli-reference.md`, `llms-full.txt`);
  SKILL step 7's review paragraph (and the plugin copy) says what the sheet shows, including on a
  lint-clean plan (the access graph and the main entrance or its tie); README §4's reviewer-tools
  line. `spec.llm.md` is untouched: its CLI list carries command summaries only, and `preview`'s
  summary did not change.

## Decisions

- **Where it lives: the CLI layer.** The composition reads `compile()` (twice: once plain for the
  drawing, once `annotate`d for each element's drawn nodes), `resolvePlan()` (element spans and
  shapes), `describe()` (the access graph) and `lint()`; it feeds none of them. It is pure apart from
  that (no I/O, time or randomness), so the SVG is deterministic and pinned by hash.
- **One mark per diagnostic.** `compile()`'s warnings plus the default-ruleset `lint()`'s, for the
  storey drawn (a diagnostic with no `level` shows on every storey), never merged: two warnings
  from one statement are two marks (round 1 found the first build's dedupe collapsing a `for` body's
  warnings into one mark). Numbered in source order of the span (no span last), then code, then the
  order raised. Over the examples and the defect corpus no diagnostic is duplicated across the two
  channels, so dropping the dedupe moved no count there.
- **Span to element, and no ring on a guess.** The narrowest resolved element whose statement
  contains the diagnostic's span, in the file the span is measured in (an element placed from an
  imported component is matched by its `_file`). Several elements share a span when a statement is
  repeated (a `for` body, a component placed twice). Then exactly one tied element whose id a hint
  quotes wins; else, when exactly one door, window or opening is quoted and the tied elements are
  rooms, the one room nearest that connector (inside, or by distance to its floor outline) wins,
  if no other room is as near. Otherwise the mark rings **nothing** and the legend says "(in a
  repeated statement, N copies; the warning does not say which)". The first build rang the first
  copy, which on `p2-for` was the reachable room. Exact attribution waits on diagnostics carrying
  an element id; that evidence is added to PS4.6.
- **Room overlap rings both rooms.** `W_ROOM_OVERLAP`'s span holds one room. The other is found by
  the label the message quotes, and is ringed when exactly one room on the storey has that label.
  Otherwise it is not ringed and the legend says why (the label repeats: N copies; or no room has it
  as a label, e.g. an unlabelled room named by its use).
- **Why a mark rings nothing** (`unringed.reason`): `whole-plan` (no span), `imported` (the span is
  in an imported file and no placed element comes from it), `no-element` (the span is in no element
  statement: the title block, the sheet), `repeated` (above), `not-drawn` (the element draws nothing
  on this storey).
- **Ring shapes.** A room: its floor outline (polygon, circle or rectangle), a translucent band plus a
  dashed line. A wall: its centreline as a band of its thickness plus a pad each side. A door,
  window or opening: a circle about its centre, radius half its width plus a pad. Anything else
  (furniture, column, stair …): a rounded rectangle around every point its own scene nodes draw. That
  last is a drawing annotation enclosing drawn ink, not a derived position, so the shape law is not
  engaged. The pad is 1/120 of the page's longer side. Every `ringed[].box` is the drawn ring's outer
  edge (a room's grown by half its band, a wall's by half its thickness plus the pad).
- **Tag placement.** Each element's tag goes at the first outward corner of its ring box (NE, NW, SE,
  SW) whose tag box (sized from `textWidth`) misses every ring box and every tag placed before it,
  else NE. Entrance captions sit in a layer above the rings, tags above both.
- **What is cropped, and how many.** Doors, windows, openings and furniture (the card's "junction /
  opening / clearance"); rooms and walls are ringed but not cropped. One tile per element. At most
  `REVIEW_MAX_CROPS` = 24 tiles, the first in mark order; the rest are `cropsOmitted` in `--json`
  and counted in the strip's heading.
- **Fixed scale.** Every tile is 0.25 sheet units per mm (1 m = 250 units on a 1,600-unit-wide sheet,
  scaled to `--width`), at least 2,400 mm square and the element's extent plus 600 mm each side,
  capped at the sheet's inner width. Tiles flow left to right and wrap.
- **Default output** `<name>.review.png`, so it never overwrites the plain preview.
- **Refusals.** `--review` with `--ascii`, `--view` or `--overlay` exits 3 (the sheet is a PNG of the
  plan with its own overlay). A broken plan takes `preview`'s own failure path (exit 2; with
  `--error-svg`, the error card), handed the source already read so stdin is not read twice.
- **Multi-storey.** One sheet per storey, chosen with `--level` exactly as `preview` does (default the
  lowest).

## Open

- Attribution inside a repeated statement is exact only where a hint quotes an id: PS4.6 (an element
  id on every diagnostic) makes it exact everywhere.
- `W_ROOM_OVERLAP`'s second room is found by its label; an unlabelled room (named by use or place)
  or a repeated label is not ringed, and the legend says so.
- The legend grows with the warning count (301 entries on `p8-many`); only the close-ups are capped.
- Tags still fall back to NE when every corner is taken (furniture inside a flagged room always is,
  since the room's ring box covers it).
- The access graph of an upper storey shows every room as not reached: `describe().access` reads each
  storey from its own entrances, and an upper storey has none. The drawing reports the fact as
  `describe()` states it; a stair-aware reading is a `describe()` question, not a drawing one.
- The sheet does not draw `validate --intent` findings; a reviewer runs that separately.
