# PS4.5 as built: `impact` reports `held` through room-edge contacts

Dated 2026-10-26 (branch `feat/impact-held-contact-ps45`). The card: the widening drill's `impact`
(PR #240) printed `Held (0): none`, because the shell and the partition `p` are written in numbers
and depend on nothing, so `held` had nothing to flag when room `a` widened past them.

## What shipped

- `src/analyze/contacts.ts`: the contact fact. For an authored wall, each straight segment whose
  centreline is collinear with a rectangular room's edge line and overlaps it by a positive length;
  for a furniture piece, its back edge (the footprint side `backEdgeOfDeg(rotate)` names) the same
  way. Collinear means equal in half-lattice units (`keepHalfOf`: the 0.001 mm lattice of ADR 0022,
  sign-symmetric, the scale the keep residuals use). Room edges come from the room's resolved
  rectangle (`roomEdgeLine`); a polygon, circle, unplaced or zero-size room has no named edge.
- `describe --facts depends`: `elements[].contacts: [{ room, edge }]` on an authored wall or furniture
  row, sorted by room then edge, less the rooms already in the row's `on`, at most 64
  (`MAX_CONTACTS_LISTED`, whole rooms in room-id order). The key is present only when non-empty.
  Derived walls are not elements and never get one. `depends.contacts_truncated: true` when a
  contact was left out (the 64 cap, or the storey's probe budget).
- `impact`: in `held` only, each unchanged element's before-side contacts are read against both
  sides' rooms. An edge whose line moved (`keepHalfOf(after − before) ≠ 0`), while the element's
  after-side line (`liesOnLine`) is still exactly on the before-side contact line, adds a `because`
  step `{ via: "contact", name: "<room>.<edge>", change: "moved 500 mm right", contact: { room,
  edge, axis, stayed_mm, moved_to_mm, gap_mm } }`. The human report prints one line per held row
  (so `Held (n)` counts the lines): one clause per moved line, edges that went to the same line
  joined (`wall p stayed at x 4000 while a.right / b.left moved to x 4500 (500 mm)`), clauses joined
  by `and`, then `; what it depends on changed: …` for the other steps. A truncated before side adds
  `contacts_truncated: true` and a note under Held. Contacts are never followed in a
  `changed[].why` chain: a contact does not cause a change.
- `impact`, every held row (not only contacts): an element is held only when it is EXACTLY
  unchanged (its resolved fingerprint; a wall's points, arcs, closure and thickness), not merely
  inside `diffPlans`' 10 mm tolerance. A wall that moved 5 mm with the `let` it reads followed it.
  A wall `diffPlans` calls `moved` or `resized` is in `changed` and is never held.
- Public types: `ContactFact`, `RoomEdge`, `ImpactContact`; `ImpactStep.via` gains `"contact"`.
- Docs: `docs/analysis.md` (the `contacts` row, `held[]`, the drill's report, the limits bullet).

## The drill (`widen-before.arch --set AW=4500`), verbatim

```text
AW: 4000 → 4500
Lets (1):
  AW: 4000 → 4500
Changed (3):
  room a resized (20 m² → 22.5 m²; right edge +500 mm)
    why: reads AW (4000 → 4500)
  room b moved 500 mm right
    why: on a (resized) ← reads AW (4000 → 4500)
  door door_2 re-hosted: joins a and b → nothing
    why: joins a (resized) ← reads AW (4000 → 4500)
Held (2):
  wall p stayed at x 4000 while a.right / b.left moved to x 4500 (500 mm)
  wall shell stayed at x 8000 while b.right moved to x 8500 (500 mm)
Broke (3):
  W_BOUNDARY_NO_WALL on b: …
  W_ROOM_DISCONNECTED on b: …
  W_ROOM_OUTSIDE_SHELL on b: …
Healed (0): none
Unchanged diagnostics: 1
```

The shell lay on six edges (`a.top`, `a.left`, `a.bottom`, `b.top`, `b.right`, `b.bottom`); only
`b.right`'s line moved. The top and bottom edges grew or slid along y 0 and y 5000 without leaving
them, so they are not reported.

## Decisions

1. **What "moved" means: the edge's line, not its extent.** An edge that only grows or shrinks along
   its own line still lies on the wall, so it is not held. A wall left short of a corner after a room
   grows along it is a different question, and the extent change shows under `changed` for the room.
2. **Which rooms: those the element does not already follow.** A room in the row's `on` (a
   `wall between a and b`, a piece `in a anchor …`, a wall whose points read `a.right`) is left out
   of `contacts`. The element follows it, and it is already held through `on` if it did not follow.
   An absolute `at (x, y) in r` piece does not list `r` in `on` (PS4.1), so its contact with `r` is
   recorded. This is the brief's "fixed-coordinate element", stated as a rule over the depends row.
3. **Which elements: authored walls and furniture.** These are the two the card names (a wall
   centreline, a furniture back edge). Doors, windows and openings follow their host wall. Dims,
   stairs, columns and labels are not recorded (a follow-up card if evidence asks for it).
4. **Edge names are in the resolved plan's frame** (`top` is the smaller `y`), the frame `diffPlans`
   and `impact`'s own offsets ("500 mm right") use. Elements carry no instance frame, so naming a turned
   instance's edge as its component spells it would need the composed frame per room. The
   consequence is pinned rather than hidden. `test/describe-depends.test.ts`'s equivariance suite now
   asserts that `on`/`params` do not move under a placing frame AND that every contact edge moves
   exactly as the frame moves a side (`actOnSide(fromSpelling(rotate, mirror), edge)`), over the 30
   eligible examples (24 of them with contacts) and the random-plan arbitrary.
5. **The record is id-free where it is prose.** `change` says only how far and which way. The ids
   are in `name`, `contact.room` and `contact.edge`. The human line names the element and the room
   edge by id, like every other `impact` line (`impact` is not a lint message).
6. **Not charged; bounded by counts.** `dependsFacts` runs after resolution, where there is no meter
   (`src/expr.ts`; PS4.1 made the same call). Room edges are indexed by line (map key = axis + half-
   lattice position) and, per line, by length class (`⌊log₂ length⌋` in half-lattice units), each
   class sorted by start once (O(R log R)). A probe binary-searches each class's window
   `from > start − 2^(c+1)` and walks it to the first start past its end. Inside the window the
   misses start in a span shorter than any edge of the class, so for rooms that do not overlap each
   other a probe costs O(classes · log R + its contacts) = O(log² R + its contacts); a corridor's
   long edge costs its own class one search, never a walk over the short edges. Every walked edge
   counts against `MAX_CONTACT_PROBES` = 1,000,000 per storey; past it nothing more is recorded and
   `contacts_truncated` says so (a pile of coincident rooms is the one shape length classes do not
   thin). Contacts sort by a rank fixed once per storey, never by string. The first version of this
   note claimed O(log R + contacts) with one list per line: false when a long edge shares the line
   (red team, below). Measured on this branch, the contact search alone (index plus every wall's
   probe) on a loaded machine: the red team's `corridor.arch` (2,000 rooms, a 2,000 m corridor,
   2,000 walls) 57–99 ms, no truncation; a 40 × 40 grid with 82 grid-line walls 41 ms (each grid
   line touches 80 edges, so every wall is cut to 64 and `contacts_truncated` is true); 2,000
   coincident rooms under 2,000 coincident walls 291 ms, truncated by the budget.
7. **K1 (the keep weak law) is not re-taken.** Its generator may run only on the tree before keep
   code existed (`test/keep-weak-law-gen.ts`), so a re-take is not allowed. Its payload hashes
   `describe(…, { facts: ["depends"] })` and `impact --json` (`--against` itself and the first
   top-level `let` + 100). So `test/keep-weak-law.ts` strips exactly the additive content, as PS7.6
   did for `validate`'s `summary`: `withoutContacts` deletes `depends.elements[].contacts` and
   `depends.contacts_truncated` (top level and per storey), and `withoutContactHeld` removes
   `via: "contact"` steps, the held rows left with none, `contacts_truncated` and its note, the
   contact clauses of each held line (a mixed row's line goes back to `stayed; what it depends on
   changed: …`, a contact-only row's line goes), and recounts `Held (n)`. A report with no contact
   content is passed through byte for byte. Result: 269 of 269 rows green,
   digests and evaluation steps, with no baseline value edited. Plain `describe()` never carries
   `depends`, so the K1 `describe` hash without facts is not affected at all.

## Red-team round 1 (applied in one commit)

1. **"Stayed" for an element that moved with the edge by ≤ 10 mm.** `diffPlans`' tolerance called
   the red team's `p4.arch` wall `follow` (written at `(W,0) (W,3000)`) unchanged at `W` 4005, so it
   was held twice: by its contact (`a.right` moved 5 mm) and by `reads W`. Now a contact counts only
   while the element's after-side line is still on the before-side contact line (`liesOnLine`), and
   any held row needs the element exactly unchanged (decision above). `--set W=4005` and `W=4500`
   report nothing held (`test/impact-contacts.test.ts`). The exact-unchanged rule also covers the
   PS4.2 edges; no K1 corpus row moved for it.
2. **The probe cap was reachable by an ordinary shape.** One list per line made a long corridor's
   edge widen every probe's window to the whole line, so the red team's `corridor.arch` (2,000 rooms
   and walls beside a corridor) ran out of budget and 588 walls lost their contacts, which ones
   depending on statement order. Length classes fix the cost (decision 6). The test generates the
   corridor in both orders: every wall lists `c.top` and its room's bottom, no truncation, the same
   facts byte for byte. When the cap is still hit, `depends.contacts_truncated` and `impact`'s
   `contacts_truncated` and note say so (tested on a 1,000-room pile, 1,001,000 edges walked).
3. **Nits.** One held line per row with edges grouped by line, so `Held (n)` matches the lines. The
   64 cap takes whole rooms in room-id order, so the listed room set is frame-free (an edge name
   is not; a room's edges come or go together). A `resized` wall is never held (documented). Docs:
   0.001 mm off is no contact, and each value is put on the lattice by itself (not R6's difference
   rounded once); the edge is spelled as the datum reads at the plan root. The handoff PS4 row
   counts 6, and README §7 row 4 lists PS4.5.

shuffled statement order give the same facts and report).

## Limits (recorded)

- Polygon and circle rooms have no named edges, so a wall on a polygon room's side records nothing.
- Contacts are read on the lowest storey, as `impact`'s `changed`/`held` are (PS4.6).
- An element in a turned instance names the edge in the plan's frame, not the component's.
- An element that never touched the edge it should have followed (a wall 200 mm off a room's edge)
  is still not held. What that breaks shows under `broke`.
