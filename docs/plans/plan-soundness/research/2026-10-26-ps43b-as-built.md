## What A had already shipped (checked in code, not assumed)

## What shipped

- **`impact()` / `arch impact` `keeps`** (`src/impact.ts`, `keepDelta`). Present only when both
  sides resolve and either declares a keep, after `diagnostics` and before `summary`:
  `{ broke, held, healed, added, removed, unchanged_count }`, each row `{ keep, grade, level?,
  residual_mm: { before?, after? }, at?, changed }`. Matched by `(level, keep text, occurrence
  index)` (the key `repair` already used), span-blind. `broke`: broken after, and held before or
  the residual moved; `healed`: held after, broken before; `held`: held on both sides while a
  target changed or the residual moved; one-sided keeps are `added`/`removed` with their one
  residual (R15). Human lines after `Unchanged diagnostics`, as §6 words them.
- **One report of a broken hard keep.** `diagnosticDelta` drops `W_KEEP_VIOLATED` from the
  compile channel when both sides resolve, so `diagnostics.broke`/`healed`/`unchanged_count`
  never count it. When a side does not resolve nothing is compared: no `keeps` section, and the
  code stays a diagnostic (else a broken keep would vanish from the report).
- **Per-storey targets (R15's scope).** A keep's `changed` reads its targets on its own storey
  (a `stacked` keep: on every level it lists): the resolved element (a wall from `ir.walls`)
  fingerprinted without spans, internals or `label`, compared across the sides; an axis target by
  its position. So an upper-storey keep is classified exactly like a ground-floor one. **The
  element sections (`changed[]`, `held[]`) still compare the lowest storey only** (PS4.6); the
  level-2 test shows `changed: []` beside a level-2 keep `held` with `changed: ["c", "d"]`.
- **`describe --facts depends` `depends.keeps[]`** (`src/analyze/keep-facts.ts`). Every keep on
  the top-level `depends`, each storey's own on its `levels[]` entry (R16); `stacked` rows only on
  the top level (they span storeys). Row `{ keep, level?, targets, constrains, equations?, bounds?,
  locked?, implied?, implied_truncated?, redundant?, conflicts?, conflicts_truncated? }`.
  - `constrains`: the closure over the storey's depends rows (`on`, `hostWallId` with a derived
    wall's own row, `axes` → the axis block's names, `params`), the `place` reads of every instance
    a target sits in, the axis expressions of a named axis, **plus the names the keep's own value
    reads** (a `--set` of those moves the residual too, so `locked` would lie without them). The
    closure is per element, not per edge: `fixed a.left at 0` on `room a at (0,0) size W x 5000`
    reads `W`.
  - `implied` / `redundant` / `conflicts`: a weighted union-find on half-lattice integers (the
    keeps' own scale). Implications entered first: a relational room's placement edge (`right-of`,
    `below` with a literal gap; `left-of`, `above` also need the room's own size on that axis a
    literal, because the corner is snapped before the size is added), its leading cross-axis edge
    (default or `align top|left`), a trailing one (`align bottom|right`) when the own size is a
    literal; a straight wall segment whose two points write the same edge datum plus the same
    literal on the line's coordinate. R5: edges only, every literal a multiple of `grid` (an
    integer with no grid). Only the storey's body and its `zone`s are read (a loop, a branch or a
    component may not expand). Then the keeps in `describe().keeps` order; an equality whose value
    reads a name is not entered. `min clear` redundancy by demand per room; `stacked` nodes are
    their own (the footprint edge is not snapped as a datum is).
  - Measured soundness: over the 23 keep-corpus plans and one extra fixture, each re-run with every
    top-level `let` set to 0, 1, 37, 4025 and −75, every keep the source alone implies holds and
    every keep the source alone contradicts is broken (`keep-impact-depends.test.ts`).
- **PS4.11.** `planToJson()` returns `droppedKeeps` (the accepted keeps as measured, a loop's
  repeats counted per pass) when the plan declares one; `compile -f json` prints one stderr line,
  `note: Plan JSON carries no keeps; this export leaves out the plan's N keeps (the .arch source
  still holds them)`, unless `--quiet`. The language reference states it.
- **Manifest.** `validate`'s and `impact`'s output descriptions name the `keeps` keys;
  `docs/cli-reference.md` and `llms-full.txt` regenerated.
- **Teaching.** Spec line: "advisory in describe/validate/impact" (+7 units). SKILL step 8: "lists
  which keeps a change breaks, holds or heals, each with its residual before and after", replacing
  "lists it among the diagnostics a change breaks". ADR 0033: a `Built:` line under Status, and
  decision 6's parenthetical on upper storeys updated to what was built.

## Decisions taken here

1. **`implied[].by` is a list**, not the string design §9 prints: a path can run through several
   statements (`wall p at a.right`, `wall q at a.right + 100`), and `redundant.by` and
   `conflicts[].with` are lists already. Each implied and conflict entry also carries `equation`
   (the two targets as written), which §5's shape left implicit.
2. **`constrains` includes the keep's own value's names** (above), so `locked` means what it says.
3. **The note is a stderr line plus a library field**, not a Plan JSON key: a key would change the
   Plan JSON schema and every consumer's document for a fact about what the document lacks.
4. **Path walks are capped** at `MAX_KEEP_PATHS` = 64 implied and 64 conflict paths per plan;
   past it an implied entry has no `by` and the row says `implied_truncated`, a conflict is not
   listed and the row says `conflicts_truncated`.
5. **`held` also takes a moved residual** on any storey (a `min clear` margin), as R15 asked for
   upper storeys; with per-storey targets the rule is the same everywhere.
6. **K3 gains a second table (K3b)** over the new surfaces instead of widening the first, so the
   23 PS4.3a rows stand unchanged and prove nothing of A moved.

## Red-team round 1 (one blocker, four should-fixes, eight nits; all applied in one commit)

Probes: the red team's scratch directory `ps43b-redteam` (outside the repository).

1. **Blocker: id-less rooms and walls shared a node** (`|.left`), so a broken keep was called
   redundant (autoid2) and a false conflict appeared (autoid). Implications now read only rooms
   and walls written with `id=`.
2. **Lattice ties, and an amendment to R6.** Each datum was put on the lattice separately, so two
   values 0.0005 mm apart could report 0.001 mm (lat) or hide it, and the facts disagreed with
   the residual. The evaluator (`src/keep.ts`, `diffH`) now takes the difference of the values a
   keep compares, less its own `<mm>`, exactly as the numbers stand, and rounds that once
   (`sign(d)·round(|d|·1000)`, at twice the difference when a centre line is a side). **R6 as
   amended:** values are read snapped (R5) and never rounded one by one; the difference of two
   snapped values is compared after one rounding. ADR 0033 decision 2 and the language reference
   say so; `min clear`'s scan still works on values put on the lattice one by one (its clear span
   is built from many faces, not one difference). K1 (269/269) and K3 (23/23) did not move. The
   facts enter only literals on the lattice and claim a one-lattice-unit gap neither way (lat2:
   residual 0.001, neither implied nor a conflict); the soundness law now also runs every
   top-level `let` at 3.0025, 1000.0015, 0.0005 and 0.15, on no grid and on a grid of 30.
3. **`locked` ignored conditions.** `constrains` now adds the names read by every `if`/`for`/
   `while` around the keep, around each statement the closure reaches, and around each `place`
   on a target's instance path (lockif: `X`; dep1: `ON`), then follows `let` chains (`W` → `W0`,
   nit 11). The language reference no longer says "no `--set` can break it": it says what is
   followed, and that a position found by a search (`flush`) is not.
4. **Grade flips.** A keep matched across the sides whose grade differs is `broke` when it is a
   broken hard keep after and `healed` when it was one before (grade.arch: hard → advisory is now
   `healed`, with the residual 100 → 100); its row carries `grade: { before, after }` and the human
   line `(hard → advisory)`.
5. **`changed` reads what a keep reads**: a wall's points, arcs, closure and thickness; a room's
   corner, size, polygon or circle; other elements' position, size and width (door.arch: a door
   sliding on `p` no longer makes `align a.right p` held).
6. Past the path cap an implied entry has no `by`; a redundant row whose paths were all past the
   cap says `redundant: { truncated: true }`, never `by: []`.
7. `KeepImpact` rows carry `occurrence` (from 1) and `span`; the human line names an occurrence
   past the first (`(soft, occurrence 2)`). Design §9's JSON now has these two keys more per row;
   its human text is unchanged.
8. Each target's node is a map lookup (no scan of the storey per target), and `impact` builds its
   depends rows straight from its own resolve (`dependsFacts`) instead of calling `describe()`
   with `--facts depends`, so it neither resolves twice nor builds the keep facts. On the red
   team's `big2.arch` (64 walls, 4,800 rooms, 1,000 keeps of 64 targets; built CLI, two runs
   each): `describe --facts depends` 11.9 s / 11.2 s before, 9.2 s / 8.5 s after (plain `describe`
   is 8.3 s); `impact --against` itself 38.9 s / 39.5 s before, 33.0 s / 28.7 s after.
9. The Plan JSON note is printed only after the export succeeded (an unwritable `-o` prints none).
10. A keep implied through a keep of a weaker grade is `redundant_by_weaker` (its implied entry
    `by_weaker: true`), never `redundant`; the same for `min clear` demands.
13. `CHANGELOG.md`'s PS4.3a entry no longer says the rest "follows in PS4.3b"; handoff §4's PS4
    count and the open-card table are current.

K3b rows moved, each with its reason beside it in `test/keep-digests.test.ts`: `loops` (the
`for`/`if` conditions enter `constrains`, so `equal width b1 b2` inside `if N > 2` is no longer
locked; impact rows gain `occurrence` and `span`), `min-clear` and `on-axis` (implied through a
weaker keep: `redundant_by_weaker`), `offset-fixed` (a 0.001 mm gap is no longer called a
conflict), `widen-before` and `widen-after` (`occurrence` and `span`). The 23 K3 rows did not move.
