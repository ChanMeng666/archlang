# 密集图面可读：计划

2026-11-18 立项。所有者看到一张由下游应用生成的 11 个房间的办公平面图：房间名、面积、尺寸数字和指北针挤在一起，看不清。所有者 2026-11-18 批准全部修复（"全部都实施"）。卡片在 `cards.md`，续接点在 `handoff.md`。按 RM-D15，排期只在 `../product-roadmap/v3.md` §3。

## 1. 现状（核心 1.64.0，同一份源码）

那张图拥挤的主要原因不在本仓库。那次的 SVG 是 1.51.0 之前的编译器画的，生成后存档，此后没有重画，而缩小并换行房间名的 `fitLabels`（`src/label-fit.ts`）是 1.51.0 才加的。用 1.62.0 和 1.64.0 重编同一份源码，两者输出逐字节相同，房间名都已缩小、换行，落在自己的房间里。下游应用那边的修复记在它自己的私有规划里。

1.64.0 的输出仍有五处毛病，本计划逐一修掉：

| 编号 | 毛病 | lint 现在报不报 |
|---|---|---|
| AL1 | 指北针压在顶部尺寸链的数字上 | 不报：没有规则看图框元素（指北针、比例尺、图签） |
| AL2 | 短跨度的尺寸数字压在刻度和尺寸界线上 | 不报：`W_DIM_OVERLAP`/`W_DIM_INSIDE` 只看手写的 `dim` |
| AL3 | 小房间（1.5 m 宽的卫生间、储藏间）的名字和面积压在洁具上 | 报 `W_ANNOTATION_OVERLAP`，但图上不改：没有引出线，也不会放到房间外 |
| AL4 | 家具文字比家具宽（300 mm 宽的屏幕写着 "Display"） | 不报：家具文字既不算 `fitLabels` 的障碍，也不归规则检查 |
| AL5 | `dims auto all` 的墙厚数字落在房间名或面积上 | 报，但数字不挪 |

另有一处接口缺口，编为 AL6：`W_ANNOTATION_OVERLAP` 没有结构化字段说明是谁压住了谁。它的 `span` 总是指向房间语句，哪怕压在上面的是墙厚数字，所以调用方无法分辨哪些重叠是作者能改的。

## 3. 原则

1. 绘图改动不能移动语料上的 `describe()`/`lint()`。例外只有 drafting 层的 lint（ADR 0032 §4；`docs/agents/iron-laws.md`）。每个 PR 列出 drafting lint 变化的平面，其余部分用对调律证明不变（`test/byte-identity-baseline.ts` 文件头；`docs/testing.md`）。
2. 不为让测试变绿而改写金样。PNG 变了就做像素差分，并核对差分区域的外框。
3. 随包示例必须保持零警告。所以新的 lint 码要等对应的绘图修复合并之后才加。
4. lint 自己重算 `dims auto` 的数字位置（`autoDimensions()` + `dimTextPrim()`），不读 Scene。因此改数字位置的卡，必须让 `autoDimensions()` 算出同样的位置。
5. 候选位置按格点排名，不按测量出的距离排名（同 `label-fit.ts` 的做法）。新增工作计入 `MAX_FIT_WORK`；新画的东西要计入 `drawCost` 和 `bounds()`。

## 4. 工作顺序

AL6 → AL1 → AL5 → AL4 → AL3（拆成 AL3w → AL3a → AL3b）→ AL2a → AL2c。AL2b 等 AL-D1 裁定。AL3c–AL3h、AL4b、AL5b、AL6b 是这些卡的后续，排在 AL3b 之后。

- AL6 先做：后面各卡都用它来写测试。
- AL1、AL5 先于 AL2：这两张也会挪动尺寸和图框，放在 AL2 之前，可以避免金样改两次。
- AL4 先于 AL3：引出线要避开家具文字，两者共用同一套障碍模型。

## 5. 需要所有者决定的事

| 编号 | 问题 | 建议 |
|---|---|---|
| AL-D1 | 尺寸文字加底色遮罩（类似 AutoCAD 的 DIMTFILL）：所有带 `dims auto` 的 SVG/PNG 都会变 | 先不做。AL2a 之后再量剩下多少数字压在线上，再决定 |
| AL-D2 | 家具文字放不下时，能否缩到 `furnFont` 以下。`label-fit.ts` 把 `furnFont` 定为"图上最小的字" | 不缩。先试转到长边；还放不下就不画文字，文字仍留在 `describe()` 里（`schedule fixtures` 还没有，见 RM4.2） |
| AL-D3 | 房间名允许离开自己的地面，用引出线指回：这改变了"标签留在自己地面上"的约定（`label-placement.ts`） | 允许，只限 `fitLabels` 之后仍然相撞的标签，并写一份 ADR |

所有者 2026-11-18 批准实施全部修复。上表三项是实施中的具体取舍，表里的建议是默认做法，所有者可以改。
