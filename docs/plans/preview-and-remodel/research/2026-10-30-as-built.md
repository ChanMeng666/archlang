## Phase 4: `@chanmeng666/archlang-3d`

The brief and `handoff.md` said to register the trusted publisher first and publish through the workflow. npm cannot do that: the package must already exist (`npm trust` docs). So the owner published 0.1.0 by hand and registered, and the workflow published 0.1.1. `0.1.0` has no provenance; `0.1.1` does (run 41166675893, `gitHead` `f91f6a21`, predicate `https://slsa.dev/provenance/v1`).

The first dispatch (run 41160214601) failed in `prove:pack`, before reaching npm: `view --replay -o plan.html` wrote the file, then launched Chromium and exited 1 where none was installed, while the README said only a video needs a browser. Every earlier proof had run on a machine with a browser, so `0.1.0` went out with the defect. Fixed in PR #386 (merge `f91f6a21`): a browser that will not start, with no `--video`, gives exit 0, a note on stderr and `rendered: false` under `--json`. Red-team round 1 narrowed the excuse to a failed launch. Node 18 then caught the new test importing `playwright-core`, which exits the process below Node 20, so the test simulates the failure and `prove:pack` covers the real case.

Lesson: run `prove:pack` with `PLAYWRIGHT_BROWSERS_PATH` at an empty directory before a hand publish; the owner cannot take back a version.
