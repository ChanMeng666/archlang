\title{Reproducible Is Not Correct: Reflexive Gates and the Self-Descriptions We Ship to Language Models}

\author{\IEEEauthorblockN{Anonymous Author(s)}}

\maketitle

\begin{abstract}
Software increasingly ships descriptions of itself intended for a language model rather
than a person: specifications, constrained-decoding grammars, schemas, bundled context
files, and the identity a server states to its host at handshake time. Nothing executes
these against the thing they describe. The gate deployed over them is almost universally
\emph{reflexive} --- regenerate the artifact, fail on a difference from the committed copy
--- which establishes determinism and cannot establish truth. It is nonetheless sound
wherever it is deployed, because the artifacts it guards are \emph{mechanically derived}
from their subject and a derived artifact can be stale but never wrong. That precondition
is never stated and never checked; when a generator \emph{retypes} a fact instead of
deriving it, the same gate is vacuous and looks identical in CI. In a census of the
\factEcoPackages{} npm packages behind every server on a public agent-tool registry, of
the \factEcoApplicable{} whose self-reported identity resolves statically,
\factEcoRetypedPct{} retype it rather than derive it and \factEcoDriftConfirmedPct{}
state a version that once tracked the package and has since been left behind. We claim
none of the underlying concepts; we report the precondition, the artifact class, and the
measurement.
\end{abstract}

\section{The Gap}

A package meant to be usable by a language model publishes a specification for the model
to read, a grammar for a constrained decoder to sample under, schemas for its inputs,
context files bundled at pack time, and an identity it states when a host connects. None
of it is read by a person in the ordinary course of events, and none of it is executed
against the system it describes.

What guards it, when anything does, is a drift gate: regenerate and fail on a diff.
Microsoft's API Extractor regenerates a public-API report and fails a production build on
any difference from the checked-in file~\cite{api_extractor}; Bazel's Gazelle offers
\texttt{-mode=diff}~\cite{bazel_gazelle}; \texttt{terraform fmt -check} and
\texttt{cargo readme -{}-check} are the same shape; the .NET source-generator
documentation recommends snapshot testing and justifies it explicitly on the grounds that
generator output is deterministic for a given input.

That justification is the subject of this paper. A \emph{reflexive} gate --- one that
compares a generator to its own output --- establishes that the generator is
deterministic and cannot, even in principle, establish that what it emits is true. Both
halves are already in the literature and never joined: build-system theory places the
correctness of generated content outside what a build system
guarantees~\cite{mokhov2020buildsystems}, and reproducible builds adopt
byte-reproducibility as an \emph{integrity} property~\cite{lamb2022reproducible}.

The gap has not needed naming because it has not mattered. Every gate above guards an
artifact \emph{mechanically derived} from its subject: API Extractor reads a compiler's
symbol table, Gazelle reads real imports, \texttt{cargo-semver-checks} reads rustdoc
JSON. \textbf{A derived artifact cannot be wrong about its subject --- only stale.} For
derived artifacts the reflexive gate is sufficient, and its limitation has no
consequences.

\subsection{What we do not claim}

A guard that passes without its passing depending on what it appears to check is vacuous
satisfaction~\cite{ball2008vacuitytesting}, and the remedy we use --- perturb the subject
and require the guard to notice --- is Beer et al.'s procedure from
1997~\cite{beer1997vacuity}. Executing documentation against its implementation is
\texttt{@tComment}'s idea from 2012~\cite{tan2012tcomment}; CASCADE now generates tests
from documentation~\cite{kiecker2026cascade}; Rust, Go and Python run doc examples by
default~\cite{rust_doctests,go_testable_examples,python_doctest}. Requiring that declared
diagnostics can fire is shipped and CI-enforced in rustc's \texttt{tidy}
check~\cite{rustc_tidy_errorcodes}. Validating a machine-consumed description against its
subject is a decade-old practice: Pact executes a generated contract against a real
provider~\cite{pact_contract_testing} and Schemathesis executes a schema against a live
server, reporting divergence without deciding which side is
wrong~\cite{schemathesis}. Even the remedy has a name: deriving a fact once rather than
retyping it is DRY~\cite{hunt1999pragmatic}.

What is left is a precondition and a measurement. DRY says what to do; the failure mode of
the gate \emph{when DRY is violated} appears nowhere. DRY is a design rule with no
enforcement story; the reflexive gate is an enforcement mechanism whose soundness silently
depends on that rule and never checks it.

\section{Derived Versus Retyped}

Let $S$ be a system, $G$ a generator, $A = G(S)$ a committed artifact, and $A^{\ast}$ the
artifact that would be true of $S$. Call $G$ \emph{derived} when its output is a function
of $S$ alone. Then $G(S) = A^{\ast}$ by construction: the artifact cannot disagree with
the subject, because the subject is all it consulted. Its only available failure is
staleness, which is exactly what a reflexive gate detects.

Call $G$ \emph{retyped} when its output depends on facts a human transcribed into the
generator. Now $G(S)$ and $A^{\ast}$ are independent. The generator emits what its author
believed, deterministically, forever. Regenerating produces the same bytes; the gate
passes; the artifact is wrong.

A reflexive gate observes one thing: whether $G(S)$ equals the committed $A$. That
comparison is blind to how $G$ computed its answer, so two generators over the same
subject --- one derived, one retyped --- produce identical CI output, and nothing
distinguishes them. The gate has no access to the property on which its own soundness
depends. Nor is the distinction visible in a generator's source: a single generator can
be derived in one function and retyped in the next.

\subsection{A demonstration}

In the subject system --- a production open-source compiler for a small declarative
language, with \factErrorCodesTotal{} catalogued diagnostics and
\factTestFiles{} test files --- two generated artifacts describe the language: a
specification for a model to read, and a GBNF grammar for a constrained decoder. Both are
generated, both are covered by the drift gate, both had been green since they were
written. When they were first checked against the parser rather than against themselves,
the specification taught \factSpecBadLines{} incorrect grammar lines of which
\factSpecUncompilable{} do not compile, and the grammar derived
\factGbnfIllegalForms{} forms the parser rejects. \textbf{The two sets did not coincide:
each generator was right where the other was wrong, and both gates stayed green for three
releases.}

No amount of re-running either gate could have found this, since both generators
reproduced their own output exactly, which is all the gate ever asked. Comparing the
artifacts to each other would not have settled it either --- they disagree, but with no
oracle there is no way to say which is right, and in fact both were wrong in different
places. A downstream consumer generating from the specification failed
\factDownstreamFailed{} of \factDownstreamTotal{} attempts. The grammar's cost is worse in
kind: a constrained decoder sampling under an over-permissive grammar emits output the
grammar guarantees is well-formed and the parser rejects, which inverts the artifact's
only purpose.

\section{Measurement}

A protocol server states its identity to its host as a name and a version when a session
opens. That value is a machine-consumed self-description whose subject --- the package's
own published version --- is public and exact, which makes it unusually measurable.

We enumerated every server on a public agent-tool registry (\factEcoServers{} entries) and
analysed the \factEcoPackages{} unique npm packages among them. This is a \emph{census},
not a sample; the frame is registry-listed servers distributing an npm package, which is
not the same population as all such servers.

Of \factEcoApplicable{} packages whose handshake version resolves statically,
\textbf{\factEcoDerived{} (\factEcoDerivedPct{}) derive it from the package manifest and
\factEcoRetyped{} (\factEcoRetypedPct{}) retype it as a literal.} This is the field
measurement of the precondition: the reflexive-gate ecosystem is built for the first case,
its soundness depends on being in the first case, and here the first case is the minority
by an order of magnitude.

\textbf{\factEcoDriftConfirmed{} packages (\factEcoDriftConfirmedPct{}, 95\,\% CI
\factEcoDriftConfirmedCI{}) state a version that once tracked the package and has since
been left behind.} Because a stale-looking literal can also be a deliberate independent
versioning scheme, each candidate was corroborated against the package's own history: we
fetch the release the literal \emph{names} and ask whether the handshake matched the
package version \emph{then}. \factEcoIndependentVersioning{} cases were excluded on those
grounds --- the check working. The uncorroborated upper bound is
\factEcoDriftRawPct{} (CI \factEcoDriftRawCI{}). A further \factEcoNeverPublished{}
packages name a version that was \emph{never published at all}; these are not corroborable
by construction and are excluded, so the headline understates. Intervals are binomial
uncertainty about the underlying propensity, not sampling error.

The median confirmed case is \factEcoMedianReleases{} releases behind, but the tail is the
finding: \factEcoGeFive{} are at least five releases behind, \factEcoGeTen{} at least ten,
and the extreme is \factEcoMaxReleases{} releases and \factEcoMaxDays{} days.
\factEcoInternalDisagreement{} packages carry two handshake literals that disagree with
\emph{each other}. Every confirmed positive carries its own evidence in the dataset; a
hand-reviewed sample of \factEcoFpReviewed{} from the corroborated stratum found a
false-positive rate of \factEcoFpRate{} (CI \factEcoFpRateCI{}).

One package --- \texttt{@shiplightai/mcp\,0.2.1}, as published on
2026-08-22 --- carries \texttt{"0.2.1"} for its \texttt{-{}-version} flag and
\texttt{"1.0.0"} for its protocol handshake, in the same bundle. The human-facing
self-description is right; the model-facing one is not. We name it, with its version and
date, so the claim can be checked and so it can be fixed; the aggregate rate above is the
finding, and individual packages are cited only where they are genuinely illustrative.

\section{Emerging Results and Next Steps}

Three further results are in progress. First, six instances across four third-party
compilers, four verified by execution rather than by reading; the strongest is a
diagnostic that can never fire in \emph{both} the original and an independent
reimplementation in another language by another author, with the two projects' sets of
unfirable diagnostics overlapping but differing --- the shape one would predict if each
catalogue were hand-maintained. A counterexample (one project's catalogue is entirely
live) keeps the claim falsifiable. Second, a depth study of the subject system in which a
grammar agreed with its parser on \factGbnfAgreeBefore{} of \factGbnfCorpus{} corpus
plans before the fix and \factGbnfAgreeNow{} after, with the expected verdict recomputed
from the compiler on every run so there is no column to edit. Third, a remedy stated as a
requirement rather than a practice: every guard must be provably non-vacuous, by a planted
fault, by an expected value computed rather than written down, or by an anti-vacuity
assertion that a fixture is really faulty before it is healed.

One result from that third strand refines the remedy rather than confirming it, and it arrived
while this paper was being written. A documentation site rendered the language in one flat
colour because a component carried a hand-typed keyword set of \factHandTypedWords{} words with
a comment asking the next person to keep it in step with the compiler's table --- a retyped
generator with no gate over it at all, whose failure mode is that a missing word is drawn as an
identifier rather than reported. The repair is to derive it. **What was not expected is that the
hand copy was more correct than its source**: two words present in the copy were absent from the
compiler's table, where they had been missing since \factUntabledSince{} while the parser
accepted them and the specification documented them, so deriving the artifact would have
\emph{lost} them. They were found by the completeness assertion shipped alongside the
derivation. Deriving a description does not make it correct; it makes its correctness equal to
the source's, and the value of the exercise is that it forces the source's incompleteness into
view. A single-source rule with no completeness check moves the defect rather than removing it.

The open question is a detector. The reflexive gate cannot check its own precondition, but
the precondition is concrete --- \emph{does this generator's output depend on a fact a
human typed into it?} --- and for closed value sets it is mechanisable. For prose that
states a rule in natural language it is not, and there executing the documentation appears
to be the only remedy.

\subsection{Threats}

The census carries no sampling error but its frame excludes servers distributed by other
means. Packages whose version does not resolve statically are excluded rather than
guessed, and the exclusion is not random: reading a version from a manifest is itself
dynamic, so if dynamic resolution correlates with better engineering the true retyping
rate across all packages is \emph{lower} than the rate among applicable ones. We measure
whether a description is true, not whether being false caused harm in a given deployment.
Our negative claims are of the form ``we found no prior work naming this''; a major
bibliographic database was unreachable during the search, and code search at scale was
not available, so the engineering-practice sweep rests on documentation and a bounded set
of repositories. That sweep retracted two of our earlier claims, which is evidence about
its yield in both directions.

\subsection{Disclosure}

The subject system and this work's tooling were substantially co-authored with
language-model agents. We state as a hypothesis, not a result, that a model writes
\emph{plausible} meta-layer artifacts and that plausibility is precisely what a reflexive
gate cannot distinguish from truth. Falsifying it needs a comparable measurement over
human-authored projects of similar age, which we have not run; the census cannot separate
the two. The measurement stands without the hypothesis.
